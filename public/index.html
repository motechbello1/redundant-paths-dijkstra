How it works, in plain English

Think of a network as cities joined by roads. Each road has a cost, here its length in kilometres. Data travels from one city to another along the cheapest chain of roads.

Step 1: the primary path

Dijkstra's algorithm finds the cheapest path. It starts at the source, then keeps settling the nearest city it has not settled yet. Once a city is settled, its cost is final. It stops when the destination is settled. The Dijkstra step by step tab shows this happening.

Step 2: the backup path

Now every road on the primary path gets a huge extra cost, called the penalty. The penalty is the cost of every road in the network added together, plus one. Then Dijkstra runs again. Because a penalised road costs more than all the other roads put together, the second run avoids the primary roads whenever it possibly can. What it finds is the backup path.

penalty = sum of all link costs + 1

Step 3: when a road breaks

Plain Dijkstra keeps one path. When a road on it breaks, traffic stops while the break is noticed, Dijkstra runs again and the switches get new instructions. Two-pass Dijkstra already has the backup stored, so it switches as soon as the break is noticed. That is why it loses fewer packets.

What is a "trap"?

Sometimes the first path blocks the only good way around, so the second run has to reuse one road. In the Nigerian network this happens for 2 of 190 pairs: Ibadan to Katsina and Ilorin to Katsina. A fully separate pair of paths does exist for both, but two separate Dijkstra runs cannot always find it. You can open both from the Route planner tab.

Honest limits

  • The 20-city Nigerian network is hypothetical. It does not describe any operator's real network.
  • Link capacity and traffic volume are not modelled.
  • The packet-loss figures come from a simulation, not from real switches.
  • Cities with only two links stay weak: if both break, nothing can reach them.
